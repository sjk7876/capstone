\subsection{Recording Setup}
All data was collected using a fixed single-camera baseline setup designed to capture the server, ball flight, and landing zone in a single view. The camera was positioned at the center of the baseline, approximately 4 m behind the court, mounted on a 74 in (188 cm) tripod and tilted downward by roughly 5--10°. This ensured that both the near and far court lines remained visible while minimizing perspective distortion.

Recordings took place at the Rochester Institute of Technology Hale–Andrews Student Life Center volleyball courts under overhead LED lighting. Lighting conditions varied slightly between sessions, but no exposure correction or stabilization was applied; built-in video stabilization was disabled to prevent frame warping during rapid ball motion. All recordings were captured on a Samsung Galaxy S23 at 1920$\times$1080 resolution and 60 FPS, providing sufficient temporal resolution for tracking fast serves. Across six players and five sessions, a total of 113 serve clips were collected. This consistent viewpoint formed a standardized dataset suitable for training and evaluating the ball detector, tracking system, and landing estimator.

\subsection{Data Organization for Model Development}
The primary research dataset is stored in the \texttt{data/} directory, which contains raw videos, processed serve clips, extracted frames, annotations, trajectories, and metadata used for training and validating the YOLO detector and testing the full pipeline. Its structure is shown in Fig.~\ref{fig:dir-structure}.

\begin{figure}[!t]
    \centering
    \includegraphics[width=0.7\columnwidth]{assets/dir_structure.pdf}
    \caption{Directory structure.}
    \label{fig:dir-structure}
\end{figure}

Raw video recordings are stored in \texttt{data/videos/raw/YYYY-MM-DD/session\_N/}, preserving original capture dates and ensuring reproducibility. Individual serves are manually segmented using \texttt{split\_serves.py} and stored under \texttt{data/videos/processed/<player>/session\_N/} with a consistent naming scheme (\texttt{serve\_001.mp4}, \texttt{serve\_002.mp4}, etc.). Approximately 16{,}000 frames were extracted across all serves and stored in \texttt{data/frames/} for frame-level annotation and YOLO training.

Annotation files reside in \texttt{data/annotations/}. Ball-detection labels (YOLO format) and model-generated detection JSONs are stored in \texttt{ball\_detections/}, while \texttt{court\_corners/} contains per-session calibration JSON files used to compute homographies. Ball trajectories produced by SORT are saved under \texttt{data/trajectories/<player>/session\_N/}.

Metadata linking players, sessions, and serves is maintained in \texttt{data/metadata/}. The \texttt{players.csv} file contains basic player information, and \texttt{serves.csv} records serve identifiers, video paths, start and end frames, and manually annotated landing frames. This table is automatically updated by utilities such as \texttt{split\_serves.py} and \texttt{landing\_frame.py}, ensuring consistent indexing throughout the pipeline. The \texttt{datasets/} directory contains the formatted YOLO train/validation splits used during training and hyperparameter tuning.

\subsection{User-Facing Dataset Structure}
While \texttt{data/} contains the full research dataset, the end-user workflow operates entirely within the \texttt{user/} directory. This separation allows a coach or athlete to run serve analysis without interacting with the training data or internal development files.

The \texttt{user/} directory mirrors the structure of the research dataset but stores only the user's own processed videos, detections, trajectories, and results. Its main components include:
\begin{itemize}
    \item \textbf{user/data/videos/}: serve clips split from user-provided raw videos.
    \item \textbf{user/data/annotations/court\_corners/}: session-specific court-corner JSON files created interactively using \texttt{annotate\_court.py}.
    \item \textbf{user/data/detections/} and \textbf{user/data/trajectories/}: YOLO detection results and SORT tracking outputs.
    \item \textbf{user/data/calibration/homographies/}: homography files mapping image coordinates to real-court coordinates.
    \item \textbf{user/data/user\_serves.csv}: a lightweight metadata table tracking serve IDs, hit and landing frames, and landing coordinates.
    \item \textbf{user/visualizations/}: output images such as landing heatmaps, trajectory overlays, and zone-accuracy visualizations.
\end{itemize}

The automated \texttt{workflow.py} script reads and writes exclusively within the \texttt{user/} subtree, ensuring that model development and end-user analysis remain clearly separated.

\subsection{Annotation Process}
Ball detection labels were created using the open-source Computer Vision Annotation Tool (CVAT)~\cite{cvat2023}. Annotators drew bounding boxes around the volleyball on selected frames, using CVAT’s interpolation and tracking features to propagate annotations across sequences. Labels were exported in YOLO format and integrated directly into the training pipeline.

As the detector improved, intermediate YOLO models were used for semi-automatic annotation. The \texttt{auto\_label\_and\_upload.py} script generated predicted bounding boxes for new frames, packaged them into CVAT tasks, and allowed annotators to correct only the remaining errors.

Temporal landing labels were collected using the \texttt{landing\_frame.py} tool, which records the first contact frame for each serve. These labels provide ground truth for evaluating the landing-frame estimator.

Court geometry was annotated once per session using \texttt{annotate\_court.py}. Annotators selected four court corners and two center-line points, which were saved to JSON files in \texttt{court\_corners/}. Homographies computed from these annotations allow all trajectories and landing points to be projected into physical court coordinates (meters).

Together, the recording setup, organized dataset structure, and multi-stage annotation pipeline yield a unified dataset supporting all detection, tracking, and serve-analysis experiments in this project.
